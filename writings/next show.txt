- value vs reference semantics
	- related to variable vs object mutation
		- the only options for types that have but one part
			- assignment is the only mutating procedure in this case since it has only one part
		- assignment can be thought of as binding (refering to another variable's value) and supplanting (overwriting so as to have another variable's value)
			- object mutation uses both in both initialization and reassignment
			- variable mutation uses only supplanting
			- reference semantics uses both but allows for the possibility that one is used for initialization and the other for reassignment as long as it can be supplanted after being bound
			- value semantics can use both as long as it is functionally the same as variable mutation
		- variable mutation is a form of value semantics, and object mutation is a form of reference semantics
	- parameter-passing strategy as well
		- strategies
			call by reference (parameter and argument use reference semantics (usually specifically binding in initialization and supplanting in reassignment))
			call by value (parameter and argument use value semantics (usually specifically variable mutation))
			call by address (call by value with first class references)
			call by name (substitution of preevaluated arguments)
			call by copy-restore (call by value where the parameters are reassigned to the arguments afterwards)
			call by unification (substitution of evaluated values)
			call by need (memoized call by name)
			call by sharing (certain types are boxed and use object mutation)
